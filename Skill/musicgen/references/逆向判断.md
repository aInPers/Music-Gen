# 逆向判断：从简报到大模型决策

`analyze` 给出的工程是**机器判断的初稿**：转谱、音色最近邻都是启发式，
真正需要判断的是「这层到底是什么」「该用采样还是合成音」「效果加不加」。
默认的**精确回放**按原始起音拼回原分轨，不做自动增益/EQ/母带压缩，也不做响度对齐——
所以默认工程的 `gain_db` 全为 0、`master_effects` 为空是正常的，不要当成「没校准」去补。
只有 `--no-exact-replay` 的旧工程才有响度对齐与自动 EQ。

这份文档给出一套可执行的判据，AI 助手按它读简报、写决策，再回灌给 `analyze`。
**所有判断都要有数据依据**（简报里的字段），不靠「听起来像」。

---

## 1. 三步工作流

```bat
:: ① 自动分析：产出工程 + 逆向简报（分轨缓存会让第③步很快）
python -m musicgen analyze input/song.mp3 -o songs/Reverse --force

:: ② 读 songs/Reverse/reverse_brief.json，按 §3 判据写 songs/Reverse/decisions.json

:: ③ 应用决策：复用已分离的分轨，只重跑转谱/重建（通常 20–40 秒）
python -m musicgen analyze input/song.mp3 -o songs/Reverse --decisions songs/Reverse/decisions.json --force
```

验收：`validate` 无警告 → `render` → 用 `analysis.json` 的段落/每轨信息复核。

> 一次只改 2–3 条轨。全量重写后如果变差，无法知道是哪条改坏的。

---

## 2. 先读什么

`reverse_brief.json` 的字段，按重要性排序：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `global.bpm` / `key` / `regions` | 速度、调性、段落边界与每段电平 | 段落命名、判断编制变化 |
| `tracks[].stem` / `layer` / `pitch_low/high` | 来自哪条分轨、第几层、音域 | 决定合并/拆分/删除 |
| `tracks[].features` | 质心、起音、衰减、谐波度、噪声度 | 采样 vs 合成、乐器归属 |
| `tracks[].candidates` | 音色最近邻概率（top 4） | 换音色的首选参考 |
| `tracks[].effects` | 峰值因数、RT60、宽度、伪回声、建议效果 | 效果链判断 |
| `tracks[].eq_suggestion` | 渲染 vs 原分轨的频谱差 | 是否补 EQ |
| `global.synth_presets` | 7 个内置合成音色与适用场景 | 选项池 |

概率是「55 维音色特征最近邻」的 softmax，不是置信度：**0.2 以上通常就算明确**，
候选之间差 <0.05 说明音色本身区分不开，此时优先看 `features` 与音域。

## 3. 判据

### 3.1 采样音色还是合成音色

| 观察 | 判断 |
| --- | --- |
| `features.attack_s > 0.15` 且 `sustain_ratio > 0.6`、`harmonicity > 0.7` | 持续音层 → **合成垫**（`warm_pad`），采样弦乐往往过于「有弓感」 |
| `features.flatness > 0.2`、`centroid_hz > 3000`、候选是鼓/镲 | 噪声型层 → `air_texture`，或直接删掉 |
| `attack_s < 0.05`、`decay_s > 0.4`、`harmonicity > 0.8`、音区中高 | 拨弦/键盘 → 先信 `candidates`；采样吉他与 `pluck_string` 都可 |
| `decay_s < 0.15`、`sustain_ratio < 0.2`、音区低 | 打击型低音 → `deep_bass` 或 `bass` |
| 音域有明确物理上限（如 41–330Hz 连续、候选 cello/bass 接近） | 真实低音乐器 → 保留采样，别换合成 |
| `pitch_low`–`pitch_high` 跨越 >30 个半音且候选分数接近 | 一层混了多个乐器 → 先 `split`（见 3.2），不要硬选一个音色 |

合成音色的写法：`"instrument": "synth"` + `"patch": "<内置名 | synth_patches 里的键 | 脚本路径>"`。
需要贴合原曲时，用 `synth_patches` 现场写一份（字段见 `references/合成音脚本.md`），
比硬套内置音色更接近；改完用 `synth check` 自检电平。

### 3.2 分层与删轨

| 观察 | 判断 |
| --- | --- |
| 同一条 `other` 拆出 2–3 层，各层音域不重叠、`notes` 都 ≥ 8 | 分层成立，分别判音色 |
| 低层 `notes` 少、`pitch_low < 45`、`sustain_ratio < 0.3` | 多半是低音残响 → `delete` 或并入低音轨 |
| 某轨 `confidence < 0.35` 且 `notes < 10` | 误检候选 → 先 `delete`，渲染后再决定是否补 |
| 两条轨 `stem` 相同、音域重叠 > 60%、音色候选一致 | 重复检出 → 删掉音符少的那条 |
| `notes` 极多（>800）而 `pitch_high - pitch_low < 12` | 复音过检（一个和弦被拆成单音碎屑）→ 降 `--max-polyphony` 重跑，而不是靠决策修 |

### 3.3 效果链

先看 `effects`（该分轨的整体统计），再看 `eq_suggestion`（渲染与原轨的差）。

| 指标 | 阈值 | 动作 |
| --- | --- | --- |
| `crest_db` | < 9 | 原曲动态已被压扁 → `{"type":"compressor","threshold":-20,"ratio":3}` |
| `crest_db` | > 22 | 动态大，**不要**加压缩 |
| `rt60_s` | 0.6–1.6 | 有可闻混响 → 轨道 `reverb` 0.2–0.35（写进 `decisions` 不支持，改工程或用 `track edit`） |
| `rt60_s` | > 2.0 | 长混响/氛围 → 影响转谱清晰度，考虑把该轨 `gain_db` 降 2–3dB |
| `echo_ms` | 120–900 且不被 BPM 命中 | 明确延迟 → `{"type":"echo","time":<值>,"mix":0.2}` |
| `echo_ms` | 0 | **不要**凭感觉加延迟 |
| `width` | < 0.2 | 声场窄 → `{"type":"stereo","width":1.4}` 或 `pan` 微调 |
| `width` | > 0.8 | 已经很宽，别再加宽 |
| `flatness` > 0.25 且 `crest_db` < 14 | 失真/饱和迹象 → `{"type":"drive","amount":0.15}` |
| `eq_suggestion` 的 low/high | 绝对值 ≥ 2dB | 原样写进 `{"type":"eq","low":…,"high":…}`；≥6dB 说明音色选错了，先换音色 |

`eq_suggestion` 是**渲染结果与原分轨的差**，方向是「补差」：
`low: +3` 表示渲染比原曲少 3dB 低频，要加 3dB。别反过来。

### 3.4 段落命名

`regions[]` 只有边界与统计，没有名字。按结构与电平判断：

| 观察 | 通常命名 |
| --- | --- |
| 第 1 段 8–16 秒、`rms_db` 比全曲低 3dB 以上、`onsets_per_second` 低、分轨少 | `intro` |
| 人声分轨电平最高、鼓组完整、`stems.vocals > -18` | `verse` 或 `chorus` |
| 相邻两段结构相同、后一段整体 `rms_db` 高 1–2dB、宽度更大 | 后一段是 `chorus` |
| 时长 4–8 秒、电平骤降或乐器只剩 1–2 条 | `bridge` / `breakdown` |
| 最后一段 ≤ 10 秒、逐段衰减 | `outro` |

判定不确定就留空：`regions` 只是注释，不影响渲染。

### 3.5 什么时候接受「近似」

不要试图修到「听起来一样」——这是转谱，不是解混音：

* **鼓**：底鼓/军鼓同时响时只保留一个；密集段落鼓件会互相遮挡。可接受。
* **人声**：已经是原分轨的音频轨，音色和唱腔都是原的；代价是没有音符，不能在卷帘里改唱。可接受，不要在简报里给它找音色候选。
* **失真吉他**：转谱只能得到基频与包络，泛音结构靠 `drive` 近似。可接受。
* **混响/母带**：不还原，只做音量平衡。可接受。

真正值得修的是：**整层音色选错**、**误检成多轨**、**电平明显失衡**。

## 4. decisions.json

```json
{
  "version": 1,
  "description": "副歌 pad 换合成音，删掉低音残响",
  "regions": [{"index": 2, "label": "chorus"}],
  "synth_patches": {
    "air_pad": {
      "name": "air_pad", "gain": 0.18,
      "oscillators": [{"wave": "saw", "detune": -9, "level": 0.5, "pan": -0.3},
                      {"wave": "saw", "detune": 9, "level": 0.5, "pan": 0.3}],
      "amp": {"attack": 0.7, "decay": 1.5, "sustain": 0.8, "release": 1.8},
      "filter": {"cutoff": 1400, "resonance": 1.0, "env": 700}
    }
  },
  "tracks": [
    {"track": "其他 低音区", "action": "delete",
     "reason": "notes 5、sustain_ratio 0.1、pitch_low 38，判为钢琴低音残响"},
    {"track": "其他 高音区", "action": "retimbre", "instrument": "synth",
     "patch": "air_pad", "name": "Pad",
     "gain_db": -7, "pan": 0.15,
     "effects": [{"type": "eq", "low": -3, "high": 2},
                 {"type": "chorus", "mix": 0.3}],
     "reason": "attack 0.42s / sustain 0.85，候选 synth_pad 0.31 领先采样弦乐"}
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `track` | 轨名（简报里的 `tracks[].name`）或 1-based 的 `id`；也可用 `stem` + `layer` 定位 |
| `action` | `keep`（只改名/电平/效果）/ `retimbre`（换音色）/ `delete` |
| `instrument` | 注册表键；配 `patch` 时写 `synth` |
| `patch` | 内置名、`synth_patches` 的键、或相对决策文件的 `.synth.json` 路径 |
| `name` / `gain_db` / `pan` | 覆盖自动值；给了 `gain_db` 就不再被自动校准覆盖 |
| `effects` | 整链替换（最多 12 个），按顺序串联 |
| `reason` | 一句话依据，会写进 `analysis.json` 的 warnings，便于回溯 |

约束：

* `track` 匹配不到就**静默忽略**（不报错），所以拼错名字等于没改——改完看 `analysis.json` 的 `decisions` 与 warnings。
* `instrument` 换成采样乐器时，`patch` 必须省掉，否则还是脚本音色。
* 效果参数越界会被夹取，未知效果/参数直接报错（解析阶段就失败，不会写出半成品）。

## 5. 自检清单

```bat
:: 脚本能不能跑
python -m musicgen synth check songs/Reverse/synths/air_pad.synth.json

:: 工程有没有问题
python -m musicgen validate songs/Reverse/Reverse.musicproj

:: 渲染并看每轨峰值（差 10dB 以上说明电平失衡）
python -m musicgen render songs/Reverse/Reverse.musicproj -o songs/Reverse/rebuilt.wav
```

* 每轨峰值落在 0.05–0.45 之间较正常；某轨 <0.02 基本等于没声音。
* `analysis.json` 的 `warnings` 应只剩音色库缺失、低置信度等已知项；人声不再产生「没检测到旋律」警告。
* 第二次跑 `analyze --decisions` 必须复用分轨（日志出现「复用上次的分轨缓存」），否则会白等几分钟。

## 6. 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 按「像不像」拍脑袋换音色 | 越改越糊 | 用 `candidates` + `features` 判断，写 `reason` |
| 给每条轨都加 compressor | 整体失去动态 | 只有 `crest_db < 9` 才加 |
| 把 `eq_suggestion` 当「原曲的 EQ」 | 方向反了，越补越差 | 它是「渲染缺什么」，直接写同向数值 |
| 用 `delete` 修复音过检 | 丢音符 | 降 `--max-polyphony` / 调 `--min-note` 重跑 |
| 一次改十几条轨 | 无法定位问题 | 每轮 2–3 条，渲染复核后再下一轮 |
| 写了 `patch` 却用采样乐器名 | `patch` 优先，音轨仍会变成 `instrument="synth"`，但语义混乱 | 用 `instrument: "synth"` + `patch`；要换回采样就别写 `patch` |
