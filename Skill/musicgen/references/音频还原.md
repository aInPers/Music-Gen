# 音频还原：把成品歌拆回工程

> 什么时候读：用户给的是**一段音频**，要求转成工程、改配器、取旋律、做伴奏或扒谱，
> 而不是从零「写一首」。目标是产出一个能 `render`、能继续编辑的 `*.musicproj`。

## 1. 它做什么

```
音频 → Demucs 分离（人声/鼓/贝斯/钢琴/吉他/其他）
     → 人声：整条分轨写成一条 <audio> 音频轨（不转谱）
     → 其余分轨：FFT 转谱（音高、时值、力度）
     → 音色识别（把「其他」拆成小提琴/大提琴/小号/竖笛）
     → 写工程（bpm、拍、音轨参数、analysis.json）
```

默认 6 轨模型 `htdemucs_6s`；4 轨模型更快，但钢琴与吉他会混在 `other` 里靠音色识别拆。
**人声永远不转谱**：气声、转音、真假声、歌词不是音符能表达的，直接引用
`stems/vocals.wav` 原样重放，工程里仍可静音/调音量/挪声像/加效果。

**三种产出，先选对**：

| 模式 | 命令 | 听感 | 可编辑性 | 适用 |
| --- | --- | --- | --- | --- |
| 默认（精确回放） | 不加参数 | ≈ 原曲（与分轨求和相关 **0.99999**） | 音符可改；人声没有音符 | 既要保真又要能改 |
| 纯音频轨 | `--audio-tracks` | = 原曲（0.997） | 只能调增益/声像/效果 | 只要保真、不打算改 |
| 旧转谱模式 | `--no-exact-replay` | GM 音色重放，会变 | 每个音都能改 | 复现老工程/调试算法 |

默认模式叫「精确回放」：按每条分轨的原始起音切成首尾相接的立体声块，
块外由 `beds/` 补全轨原样填回，块 + 补全 = 原分轨。**默认状态听起来就是原曲，
改某个音的时值/音高，那一处才偏离原音。**

## 2. 前置

- `torch>=2.1` + `demucs>=4.1`（`python -m pip install -r requirements.txt`）
- 首次运行下载权重约 300MB；国内先设镜像：

  ```bat
  set HF_ENDPOINT=https://hf-mirror.com
  ```

- **不需要 ffmpeg**：项目自己用 soundfile 解码，再喂给 `separate_tensor`
- 音色模板要用采样音源；至少把常用几件下好：

  ```bash
  python -m musicgen samples fetch --instrument piano,guitar,bass,vocal,violin,cello
  ```

## 3. 命令

```bash
# 保真优先：分轨直接进工程（最快，约 20 秒/首）
python -m musicgen analyze input/song.mp3 -o songs/Reverse-Audio --audio-tracks

# 可编辑：转谱成音符（默认模式）
python -m musicgen analyze input/song.mp3 -o songs/Reverse

# 速度检测不准时手动指定；保留原始律动不量化
python -m musicgen analyze input/song.mp3 -o songs/Reverse --bpm 96 --quantize off

# 快跑：4 轨 + 不保存分轨
python -m musicgen analyze input/song.mp3 -o songs/Reverse --model htdemucs --no-stems

# 改完参数重跑（分轨缓存会复用；要重分离加 --no-reuse）
python -m musicgen analyze input/song.mp3 -o songs/Reverse --force --min-note 80
```

| 参数 | 默认 | 怎么选 |
| --- | --- | --- |
| `--bpm` | 自动 | 报告里 `bpm_confidence < 0.25` 或明显是半速/倍速时手动给 |
| `--quantize` | `1/16` | **精确回放下不生效**（音符按原始起音写，不吸附网格）；只在 `--no-exact-replay` 时用于量化 |
| `--no-exact-replay` | 关 | 关掉精确回放：回到量化 + 逐事件采样 + 自动增益/EQ/母带压缩的旧行为 |
| `--min-note` | `65` | 误检碎片多就调大到 80–100；快速音阶多就保持 65 |
| `--model` | `htdemucs_6s` | 要钢琴/吉他分轨就用默认；只要人声伴奏可用 `htdemucs` |
| `--max-polyphony` | `6` | 钢琴/吉他可 6；贝斯固定 1；误检和弦太多试 3–4 |
| `--vocal-instrument` | `vocal` | **已废弃**：人声固定为音频轨，参数不再生效 |
| `--no-stems` | 关 | 不保存分轨 WAV；但 `stems/vocals.wav` 仍会写出（人声音频轨要用） |
| `--no-reuse` | 关 | 换了模型或发现分轨有残留时 |
| `--audio-tracks` | 关 | 只分离不转谱，工程里是 6 条 `<audio>` 音频轨 |
| `--no-layers` | 关 | 不把「其他」按音区拆层（默认拆 2–3 层） |
| `--max-layers` | `3` | 每条分轨最多拆几层 |
| `--no-brief` | 关 | 不写 `reverse_brief.json`（默认写出，供判断） |
| `--no-auto-eq` | 关 | 不按「渲染 vs 原分轨」的频谱差自动补 EQ（精确回放本来就不补） |
| `--decisions` | 无 | 应用决策文件：换音色/脚本/效果/删轨/段落标签 |

## 4. 产出

```
songs/Reverse/
├─ Reverse.musicproj
├─ tracks/01-vocal.track.xml   ← 人声音频轨（<audio>，没有 <note>）
├─ tracks/02-bass.track.xml    ← 贝斯（可编辑音符）
├─ tracks/03-...                ← 鼓 / 钢琴 / 吉他 / 识别出的其他乐器
├─ samples/<分轨>_b*.wav        ← 精确回放的立体声时间轴块（块上带 srcTime）
├─ beds/<分轨>.wav              ← 补全轨：块覆盖区间置零，块+bed = 原分轨，不能删
├─ stems/vocals.wav             ← 人声音频轨引用的文件，不能删
├─ stems/*.wav                  ← 其余分离结果，用来对照试听
└─ analysis.json                ← bpm / key / 每轨置信度 / exact_replay / 警告
```

`analysis.json` 里重点看：

- `bpm`、`bpm_confidence`、`key`：决定要不要 `--bpm` 重跑、工程标题写什么调
- `tracks[].confidence`：低于 0.4 的轨，乐器归属基本要人工改
- `warnings[]`：音色库缺失、置信度低等（人声不再有「没检测到旋律」这类警告）
- `stems.vocals.audio`：`stems/vocals.wav`；`stems.vocals.notes` 恒为 0

> 默认还会写 `reverse_brief.json`（段落、音色指标、候选、效果估计）并把「其他」按音区拆层。
> 要精修音色/效果，读 `references/逆向判断.md`：按简报写 `decisions.json`，再
> `analyze ... --decisions` 回灌，分轨会复用，通常 20–40 秒。

## 5. 还原后怎么用：先分清「保真」还是「改谱」

默认精确回放的工程是**听感保真**用的：块 + 补全轨拼回原分轨，音符只是「把手」。所以：

- **不要为了「删误检」去删音符**——补全轨已经把该块区间挖空，删了就是**静音**，不是恢复正常；
- 改 `time` 会把那块整体挪走，原位置由补全轨补上、新位置按你的时间发声；
- 改 `dur` 会让片段被截断并淡出，不再是原样；
- 改音高目前**不会变速**（片段原样播），要改音高得删掉该音符的 `sample` 属性，让它改走采样乐器；
- 想恢复某处原音，最稳的是重跑 `analyze`（分轨有缓存，通常几分钟内）。

要**精修谱面**（删误检、改配器、重写声部），用旧模式另出一份工程：

```bash
python -m musicgen analyze input/song.mp3 -o songs/Reverse-Edit --no-exact-replay
```

那一份才是「可编辑的转谱」，清理流程也只对它有意义：

1. **先听分轨**：`stems/vocals.wav` 等逐个听，确认 Demucs 分得干不干净。
   人声里残留鼓点 → 换 `htdemucs_ft` 或接受；某轨几乎静音 → 该轨可删。
2. **看报告**：`python -m musicgen info songs/Reverse/Reverse.musicproj` 看音符数与参数；
   打开 `analysis.json` 核对 bpm/key 与低置信度轨。
3. **删误检**（仅 `--no-exact-replay`）：界面里按 `Ctrl+Shift+I` 只看单轨，重点删——
   - 与时值网格错半拍、只出现一次的短音（`dur` 很小、`vel` 很低）
   - 同一时刻相差 12 半音的「八度影子」（谐波误检）
   - 超出生源音域的极端高/低音（`render` 会警告并换合成器）
   - 鼓轨里密到不可能演奏的连续同件（人声齿音/贝斯瞬态串进来的）
4. **改配器**（仅 `--no-exact-replay`）：把识别成钢琴的分解和弦改给吉他；
   给主旋律加 `reverb`，鼓轨保持干。人声是音频轨，属性面板里的「乐器」是锁住的——
   要换唱只能替换 `stems/vocals.wav` 或另找人声素材。
5. **渲染验收**：`render` 后与原始音频 A/B；重点听
   - 速度是否漂（全曲逐步错位 = bpm 错，用 `--bpm` 重跑）
   - 低音是否糊（贝斯轨音符过密，删到主要根音）
   - 伴奏与人声的电平比例（人声轨是原电平，必要时调它的 `gain`）

## 6. 精度边界（交付时必须说明）

| 情况 | 表现 | 建议 |
| --- | --- | --- |
| 干净、稀疏的编曲 | 还原度高，稍改即可用 | 直接清理误检 |
| 密集和弦 / 大混响 | 多检、漏检，和弦音缺失 | 只保留主要声部，或按和弦重写 |
| 失真吉他 / 强打击 | 音高检测被噪声干扰 | 吉他轨只留强拍，或换合成音色重写 |
| 同时敲响多个鼓件 | 只保留得分最高的一个 | 按节奏型补写 |
| 气声、转音、真假声、歌词 | 已由人声音频轨原样保留，不会丢 | 不用处理；代价是这一轨没有音符可改 |

结论：**默认精确回放听起来就是原曲**——块 + 补全轨按时间轴拼回原分轨（相关 0.99999），
音符列表只是「可编辑的把手」，不准也不影响听感。要改谱时才会偏离原音，那一处按新参数发声。
`--no-exact-replay` 的旧模式才是纯转谱，会有音色与量化偏差，别拿它交付「保真」。

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `没有可用的 Demucs` | 没装 torch/demucs | `python -m pip install -r requirements.txt` |
| 卡在加载模型 | 权重下载慢/被墙 | 设 `HF_ENDPOINT=https://hf-mirror.com` 后重试 |
| `分离模型加载失败` | HF 不可达 / 磁盘满 | 同上；检查 `~/.cache/huggingface` 空间 |
| 分析很慢 | CPU 跑 6 轨模型 | 换 `--model htdemucs`、`--no-stems`、`--device cpu` 明确指定 |
| 目标已存在 | 上次跑过 | 加 `--force`（分轨缓存仍会复用） |
| 速度明显不对 | 八度误判 | `--bpm` 给实际值（常见 70–160） |
| 打开工程提示音频文件不存在 | 只搬了 `.musicproj`，或删了 `beds/` | 连 `tracks/`、`beds/`、`stems/`、`samples/` 一起搬 |
| 卷帘里音符又多又短、网格 50% | 精确回放按起音分块、不量化，属正常 | 不用处理；听感由块与补全轨决定 |
| 人声轨在卷帘里是空的 | 正常：它是音频轨，本来就没有音符 | 在属性面板调增益/声像/效果，或换 `stems/vocals.wav` |
| 打开工程提示人声音频文件不存在 | `stems/vocals.wav` 被删或工程被单独搬走 | 连 `stems/` 一起搬；`--no-stems` 也会写出这个文件 |
